# Feature Spec 02：線上藥師諮詢

> 狀態：規劃中（Draft）
> 分類：線上藥師/醫師諮詢
> 對應變現：付費功能為主（AI 部分免費限次）
> ⚠️ 法規敏感：受《藥事法》規範，命名與服務範圍須謹慎

---

## 1. 功能總覽

提供使用者向 AI 藥師或真人藥師提問用藥相關問題的管道。透過「分流」設計，常見問題由 AI 即時回覆，需要專業判斷的問題轉介給真人藥師。

> **命名建議**：對外文案統一使用「藥師諮詢」、「用藥諮詢」，避免使用「醫師諮詢」「線上看診」等可能觸碰《醫師法》遠距醫療規範的字眼。

包含子功能：
1. AI 藥師對話（含分流）
2. 真人藥師預約制
3. 圖片諮詢（拍藥品/處方/症狀）
4. 諮詢紀錄保存與回顧

---

## 2. 目標使用者

- 對自己的藥品有疑問但不想跑醫院/藥局的使用者
- 慢性病患者用藥調整、副作用詢問
- 需要短期建議（如：感冒能不能跟血壓藥一起吃）的使用者

---

## 3. 使用者故事

- US-2.1：身為使用者，我想問「降血壓藥可以跟感冒藥一起吃嗎」，AI 立即給我建議。
- US-2.2：身為使用者，當 AI 判斷我的問題複雜，我希望能直接預約真人藥師。
- US-2.3：身為使用者，我想拍我的藥粒照片問「這顆是什麼藥？該怎麼吃？」。
- US-2.4：身為使用者，我希望能回頭翻閱過去諮詢紀錄，避免重複提問。

---

## 4. 子功能規格

### 4.1 分流設計（Triage）

```
使用者提問
    ↓
AI 第一線回覆（Claude/Gemini）
    ↓
AI 判斷信心度 / 問題類型
    ├─ 高信心 + 一般問題 → AI 直接回答
    ├─ 中信心 → AI 回答 + 提示「建議諮詢藥師」
    └─ 低信心 / 醫療判斷類 → 引導使用者預約真人藥師
```

**自動轉介條件**：
- 問題涉及處方藥調整
- 問題涉及孕婦/哺乳/兒童/重大疾病
- 使用者明確要求「我要問真人」
- AI 回覆信心度低於門檻

### 4.2 AI 藥師對話

- 多輪對話（保留 context）
- 支援文字 + 圖片輸入
- 引用個人用藥資料（需使用者授權）以提供個人化回覆
- 每則回覆附「免責聲明」：本回覆僅供參考，緊急狀況請就醫
- 回覆內容須避免「診斷」「處方建議」等用語

### 4.3 真人藥師預約

| 項目 | 內容 |
|---|---|
| 預約方式 | 選擇藥師 → 選時段 → 填寫問題摘要 → 付款 → 確認 |
| 諮詢形式 | 文字聊天（MVP）/ 視訊（Phase 2）|
| 時長 | 15 / 30 分鐘 方案 |
| 取消政策 | 諮詢前 24h 可免費取消 |
| 結束後 | 藥師可附上書面建議摘要 |

**藥師端**（B 端，獨立規劃）：
- 排班管理、諮詢工作台、收入結算

### 4.4 圖片諮詢

- 支援：藥品照片、處方箋、皮膚反應/症狀照片（非診斷用途）
- AI 先用 vision API 解析，再進入對話流程
- 圖片在對話結束後可選擇保存到「諮詢紀錄」

### 4.5 諮詢紀錄保存

- 所有諮詢（AI / 真人）按時間軸保存
- 可搜尋（依關鍵字、藥名、日期）
- 可標記重要紀錄、加入收藏
- 可匯出 PDF（與 spec 01 PDF 匯出整合）

---

## 5. 資料模型（草案）

```
Consultation
 ├─ id, profile_id, type (ai/human), status
 ├─ pharmacist_id (nullable)
 ├─ started_at, ended_at
 ├─ Messages []
 │    ├─ sender (user/ai/pharmacist)
 │    ├─ content (text/image)
 │    └─ timestamp
 ├─ summary (藥師結案摘要)
 └─ tags []
```

---

## 6. 變現分層

| 子功能 | 免費版 | 付費版 |
|---|---|---|
| AI 藥師諮詢 | 每月 3 次對話 | 無限 |
| 圖片諮詢 | ❌ | ✅ |
| 真人藥師預約 | ❌ | ✅ 或單次付費（NT$ XXX/次）|
| 諮詢紀錄保存 | 近 30 天 | 永久 |

---

## 7. 技術考量

- AI：復用 Claude / Gemini API；建立「藥師人格」System Prompt
- 對話 context 管理：每位使用者獨立 session，過長對話自動 summarize
- 真人藥師端可採 Web 介面（藥師通常用電腦工作）
- 訊息系統：建議使用 WebSocket / Firebase Realtime DB
- 金流：街口 / Line Pay / 信用卡 / Apple Pay / Google Pay

---

## 8. 風險與相依

- **法規**：
  - 真人藥師服務須確認藥師有合法執業登記
  - 不可進行「診斷」「處方」行為
  - 諮詢內容須清楚標示「不取代醫師診療」
- **個資**：諮詢內容含敏感健康資料，須加密儲存
- **AI 幻覺風險**：用藥建議錯誤可能造成傷害
  - 強制 disclaimer
  - 高風險問題自動轉介真人
  - 內容定期由藥師抽查
- **依賴**：需先有「藥師合作」B 端流程才能啟動真人預約

---

## 9. 驗收條件（DoD）

- [ ] AI 對話流暢、回覆相關且包含免責聲明
- [ ] 分流邏輯能正確識別高風險問題並轉介
- [ ] 真人預約流程可完成預約 → 諮詢 → 結束 → 摘要
- [ ] 圖片諮詢支援藥品、處方、症狀三類辨識
- [ ] 諮詢紀錄可搜尋與匯出

---
