# Feature Spec 04：社群與教育

> 狀態：規劃中（Draft）
> 分類：社群與教育
> 對應變現：免費功能，作為 SEO 與留存工具

---

## 1. 功能總覽

提供藥品知識內容，提升使用者用藥素養，同時作為 App 的留存（retention）與 SEO 流量入口。

包含子功能：
1. 藥品知識卡片（Knowledge Cards）

> 註：原本討論的「社群討論區」「用藥心得分享」暫不納入 MVP，因為內容審核成本高、有醫療謠言風險。

---

## 2. 目標使用者

- 想多了解自己用藥的患者
- 對健康/醫藥資訊有興趣的一般使用者
- 從搜尋引擎進入的潛在新用戶

---

## 3. 使用者故事

- US-4.1：身為使用者，我希望每天看到 1-3 則簡短易懂的用藥知識。
- US-4.2：身為使用者，我想收藏有用的知識卡片，日後翻閱。
- US-4.3：身為使用者，我想分享卡片給家人朋友（社群擴散）。
- US-4.4：身為使用者，我希望卡片內容與我目前用藥相關（個人化）。

---

## 4. 子功能規格

### 4.1 藥品知識卡片

**內容類型**：
| 類型 | 範例 |
|---|---|
| 藥品介紹 | 「Metformin 是什麼？怎麼吃？」 |
| 用藥常識 | 「為什麼有些藥要飯前吃？」 |
| 副作用提醒 | 「服用抗生素時常見的副作用」 |
| 季節主題 | 「流感季節用藥提醒」 |
| 迷思破解 | 「抗生素吃到症狀消失就可以停？」 |
| 食物交互作用 | 「葡萄柚與降血脂藥」 |

**卡片格式**：
- 標題（吸睛、口語化）
- 摘要（1-2 句）
- 詳細內容（200-400 字）
- 標籤（藥名、症狀、族群）
- 來源（衛福部 / 仿單 / 藥師審核）
- 相關藥品連結（可深連結到藥品詳情）

**功能**：
- 每日推播 1 則（可關閉）
- 「為你推薦」依個人用藥資料推送相關卡片
- 收藏 / 分享（含 OG image，社群好看）
- 搜尋 / 分類瀏覽

### 4.2 內容生產流程

1. **AI 草稿**：用 Claude/Gemini 從藥品資料庫批次生成
2. **藥師審核**：人工審核確保正確性（合作藥師或內部）
3. **發布**：審核通過後上架
4. **更新**：藥品仿單變更時觸發 review

> 內容是醫療類 App 的核心信任資產，**不可未經審核直接發布 AI 生成內容**。

## 5. 資料模型（草案）

```
KnowledgeCard
 ├─ id, title, summary, content
 ├─ category, tags []
 ├─ related_drug_ids []
 ├─ source, reviewed_by, reviewed_at
 ├─ published_at, status
 └─ stats (views, favorites, shares)

UserCardInteraction
 └─ user_id, card_id, action (view/fav/share), timestamp
```

---

## 6. 變現分層

| 子功能 | 免費版 | 付費版 |
|---|---|---|
| 卡片瀏覽 | ✅ 全開放 | ✅ |
| 每日推播 | ✅ | ✅ |
| 收藏 | ✅ 最多 20 張 | ✅ 無限 |
| 個人化推薦 | ✅ 基礎 | ✅ 進階（更精準） |

> 知識卡片刻意全開放：免費內容能拉新、做 SEO、培養信任。

---

## 7. 技術考量

- 後台：藥師審核介面（接 admin.html / admin_routes.py 擴充）
- 內容存儲：可考慮 Markdown + DB；或全 DB
- 全文搜尋：SQLite FTS5（小規模）或 Elasticsearch（大規模）
- SEO：建議網頁版同步發布卡片內容，建立 sitemap
- OG Image：用 server-side 渲染或預先生成

---

## 8. 風險與相依

- **內容正確性**：錯誤資訊可能造成傷害，**藥師審核絕不可省略**
- **版權**：引用仿單/期刊內容須注意來源標示
- **更新成本**：藥品仿單更新時需人工觸發 review
- **依賴**：藥品資料庫（drug_database.py）需有足夠藥品基礎資料

---

## 9. 驗收條件（DoD）

- [ ] 後台可建立、編輯、審核、發布卡片
- [ ] 前台可瀏覽、搜尋、分類、收藏、分享卡片
- [ ] 每日推播能依使用者偏好/用藥推送相關卡片
- [ ] 卡片分享後社群預覽（OG image）正常顯示
- [ ] 個人化推薦對有用藥資料的使用者準確率 ≥ 60%

---
