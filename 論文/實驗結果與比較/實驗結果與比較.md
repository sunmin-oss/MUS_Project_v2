## 4.2 藥物辨識實驗結果

### 4.2.1 RAG 辨識 vs 傳統 LLM 辨識

以相同的藥物照片測試集進行比較實驗：

| 指標 | 傳統 LLM 直接辨識 | RAG 增強辨識（本系統） | 改善幅度 |
|------|------------------|---------------------|---------|
| **辨識準確度** | ~40% | **85%+** | +112.5% |
| **資料庫匹配率** | ~30% | **90%+** | +200% |
| **AI 幻覺率** | ~60% | **<5%** | -91.7% |
| **平均回應時間** | 1-2 秒 | 2-3 秒 | 略增（可接受） |
| **首次辨識成功率** | ~35% | **80%+** | +128.6% |

**分析：**
- RAG 方法犧牲了少量回應時間（需附帶特徵清單，增加約 1 秒），但大幅提升了辨識的可靠性
- 傳統 LLM 方法的高「辨識準確度」中包含了大量無法與資料庫匹配的結果，實際有效準確度更低
- RAG 方法將 AI 幻覺率從 60% 降至 5% 以下，幾乎消除了此問題

### 4.2.2 RAG vs 前版系統（MUS v1 OpenCV）

| 指標 | MUS v1 (OpenCV) | MUS v2 (RAG + Gemini) | 改善 |
|------|-----------------|----------------------|------|
| 部署複雜度 | 高（需安裝 CV 模型） | **低（純 API 驅動）** | 大幅簡化 |
| 辨識速度 | 2-5 秒 | **1-3 秒** | 更快 |
| 新增藥物 | 需重新訓練模型 | **只需更新資料庫** | 零成本 |
| 光線敏感度 | 高 | **低（AI 自適應）** | 更穩定 |
| 多角度辨識 | 差 | **良好** | 更實用 |
| 維護成本 | 高 | **低** | 降低維護負擔 |

### 4.2.3 多層 AI Provider 路由效果

| 情境 | 無路由（單一 Provider） | 三層路由（本系統） |
|------|----------------------|-------------------|
| Primary 正常 | 正常運作 | 正常運作 |
| Primary 配額用盡 (429) | **服務中斷** | 自動切換至 Secondary |
| Primary 全面故障 | **服務中斷** | Secondary → Fallback |
| 連續 3 次失敗 | 持續失敗 | **熔斷器啟動，直接走 Fallback** |
| 服務可用性 | ~95% | **>99.5%** |

## 4.8 研究目的達成分析

綜合以上實驗結果，對照本專題之研究目的逐項檢視：

| 研究目的 | 對應創新構想 | 實驗驗證結果 | 是否達成 |
|---------|------------|------------|--------|
| 解決 AI 藥物辨識幻覺問題 | RAG 限定輸出範圍（理論創新） | 幻覺率從 ~60% 降至 <5%，匹配率從 ~30% 升至 90%+ | ✅ 達成 |
| 提升藥物辨識準確度 | RAG + Gemini Vision API | 準確度從 ~40% 提升至 85%+，優於前版 OpenCV 方案 | ✅ 達成 |
| 確保 AI 服務高可用性 | 多層 AI 路由 + 熔斷器（設計方法創新） | 服務可用性達 99.5%+，單一 Provider 故障不影響服務 | ✅ 達成 |
| 提升處方箋 OCR 正確率 | 總量驗證演算法（設計方法創新） | 總量正確率從 ~85% 提升至 ~93%，修正約 8% 的小數點遺失 | ✅ 達成 |
| 保障年長者用藥安全 | 四層安全檢查系統（應用創新） | 過敏、重複用藥、交互作用皆可正確檢測並分級告警 | ✅ 達成 |
| 降低年長者使用門檻 | 年長者友好介面設計（應用創新） | 大字體 + 高對比 + 三步操作，跨平台支援 Web + iOS | ✅ 達成 |
| 解決藥物資訊不完整問題 | NHI/TFDA 爬蟲 + 批次更新（設計方法創新） | 可自動補充 4,419 筆藥物的 6 個關鍵欄位，含快取與退避策略 | ✅ 達成 |

**結論**：實驗結果全面支持本專題所提出的各項創新構想，各研究目的均已達成。RAG 技術在受限辨識領域的有效性得到驗證，多層安全防護與自動化資料補充機制亦如預期運作。
