# 第五章：結論

## 5.1 研究問題回顧

本專題製作針對以下核心問題進行探討與解決：

1. **年長者藥物辨識困難**：口服藥物外觀相似，脫離包裝後難以辨別
2. **AI 辨識的幻覺問題**：傳統 LLM 辨識會生成不存在的藥物名稱
3. **用藥管理工具碎片化**：現有工具功能單一，缺乏整合性
4. **藥物資訊取得不便**：政府藥物資料分散於不同網站
5. **使用門檻過高**：現有藥物查詢系統介面對年長者不友善

## 5.2 解決構想與實現方法

### 5.2.1 RAG 藥物辨識

**構想**：將檢索增強生成（RAG）技術應用於藥物辨識，約束 AI 模型僅從已知資料庫中選擇藥物，從根本上解決幻覺問題。

**實現**：從 SQLite 資料庫中提取 4,419 筆藥物的視覺特徵（形狀、顏色、刻印標記等），作為上下文注入 Google Gemini 2.5 Flash 的多模態提示詞中。AI 模型在辨識時被限定只能從提供的藥物清單中選擇，確保輸出結果必然存在於資料庫中。

**成果**：
- AI 幻覺率從 ~60% 降至 <5%
- 資料庫匹配率從 ~30% 提升至 90%+
- 辨識準確度從 ~40% 提升至 85%+

### 5.2.2 一站式用藥管理平台

**構想**：整合辨識、管理、安全、諮詢四大子系統，提供從「認識藥物」到「安全用藥」的完整服務鏈。

**實現**：以 Flask 為後端框架，設計 5 個 Blueprint 模組（Auth、Medications、Safety、Consult、Admin），提供 30+ 個 RESTful API 端點。前端採用 SPA 架構（原生 JavaScript），另開發 iOS 原生 App（Swift/SwiftUI），採用 MVVM 架構模式，透過 `AppEnvironment` 實現依賴注入，以 `APIClientProtocol` 支援真實與 Mock API 切換，共計 8 個功能模組、25 個畫面。

**成果**：
- 系統整合了藥物辨識、藥單 OCR、用藥管理、服藥紀錄、安全檢查、AI 諮詢、家庭成員管理等功能
- 支援 Web 與 iOS 雙平台
- iOS App 以 XCUITest 建立 52 個 UI 自動化測試案例，涵蓋全部 8 個功能模組，通過率 92.3%
- 管理員後台提供完整的藥物資料管理、使用者管理、系統監控功能

### 5.2.3 自動化藥物資料補充

**構想**：開發爬蟲系統自動從政府網站（NHI 健保署 + TFDA 食藥署）抓取藥物詳細資訊，解決資料庫欄位不完整的問題。

**實現**：使用 Playwright（Chromium headless）開發非同步爬蟲，搭配批次更新工具、7 天快取機制、指數退避策略。導入 A3 系列效能優化：共用瀏覽器實例、精確等待、共用 DB 連線、WAL 模式等。

**成果**：
- 可自動補充 4,419 筆藥物的適應症、主成分、製造商等 6 個關鍵欄位
- 批次更新支援暫停/繼續/停止，具備即時進度顯示與 ETA 估算
- 指數退避策略有效避免被目標網站封鎖

## 5.3 創新所在

### 5.3.1 理論創新

- **RAG 技術應用於藥物辨識**：首次將檢索增強生成技術應用於台灣藥物辨識場景，提出以資料庫特徵約束 LLM 輸出範圍的方法，有效解決 AI 幻覺問題

### 5.3.2 設計方法創新

- **多層 AI Provider 路由架構**：設計三層鏈式 AI 服務路由搭配熔斷器模式（Circuit Breaker），實現 99.5%+ 的服務可用性
- **處方箋 OCR 總量驗證演算法**：提出基於 dose × frequency × days 的交叉驗證機制，自動偵測並修正 OCR 數值提取錯誤
- **四層用藥安全檢查系統**：設計過敏→重複用藥→交互作用→嚴重度分級的串聯式安全檢查流程

### 5.3.3 應用創新

- **一站式智慧用藥管理**：整合 AI 辨識、用藥管理、安全檢查、AI 諮詢於單一平台，在台灣藥物領域具有獨特性
- **iOS 原生 App 完整實作**：以 MVVM 架構開發 25 個 SwiftUI 畫面，涵蓋辨識、用藥、安全、諮詢、藥局、設定等 8 大模組，並以 52 個 XCUITest 自動化測試確保品質
- **年長者友好設計**：針對年長者群體的介面設計（大字體、高對比、三步操作），降低科技產品使用門檻
- **自動化資料補充生態**：NHI/TFDA 爬蟲 + 批次更新 + 快取系統，形成自我完善的藥物資料生態

## 5.5 未來展望

### 5.5.1 短期改進

1. **批次更新並行化**：導入多分頁並行爬蟲（Semaphore 控制並行度），將 4,400+ 筆藥物的批次更新時間從 10+ 小時壓縮至 2-3 小時
2. **Android 平台支援**：利用 Capacitor 8 將 Web 前端封裝為 Android App，實現三平台覆蓋
3. **離線辨識快取**：將常見藥物的辨識結果快取至本地，支援無網路環境下的基礎辨識
4. **使用者回饋機制**：允許使用者對辨識結果進行確認/修正，持續優化 RAG 特徵清單

### 5.5.2 中期發展

1. **Fine-tuning 專用模型**：收集足夠使用者回饋數據後，對 Vision 模型進行領域微調，進一步提升準確度
2. **藥局地圖整合**：接入 Google Maps API，提供附近藥局查詢與導航服務
3. **多語言支援**：擴展英語、東南亞語言介面，服務在台外籍人士
4. **家庭用藥共享**：允許家庭成員之間共享用藥資訊，方便子女遠端關心長者用藥情況

### 5.5.3 長期願景

1. **醫療院所整合**：與醫院 HIS 系統對接，自動同步處方資訊
2. **健保卡資料整合**：透過健保署 API 取得個人用藥歷史
3. **AI 個人化用藥建議**：基於使用者的完整用藥歷史、身體狀況，提供個人化的用藥建議
4. **藥物辨識硬體裝置**：開發專用的桌上型藥物辨識裝置，結合高解析度攝影鏡頭與邊緣 AI 運算

## 5.6 結語

本專題成功開發了「藥知道」智慧用藥管理系統，透過 RAG 技術創新性地解決了 AI 藥物辨識的幻覺問題，並整合了辨識、管理、安全檢查、AI 諮詢等完整功能。系統以 4,419 筆台灣藥物資料庫與 4,776 張實體圖片為基礎，實現了 85%+ 的辨識準確度與 90%+ 的資料庫匹配率。

本研究證明，RAG 技術在受限領域（如藥物辨識）中具有顯著優勢——透過將外部知識庫注入 AI 推理過程，可以有效約束模型輸出，解決大型語言模型在專業領域中的幻覺問題。這一方法論具有推廣至其他受限辨識場景（如化學品辨識、零件辨識等）的潛力。

未來將持續擴展系統功能與平台覆蓋，朝向成為台灣年長者最信賴的智慧用藥管理工具的目標邁進。
